## Executive decision

The research acceptance is met: each of the eight requested families has an adopt/adapt/reject disposition, an immutable source identity where inspected, licence evidence, trust-boundary assessment, source proof, and a maintenance estimate. **Add now: 0.** No candidate is approved as a Fermes runtime dependency, memory authority, commit approver, trusted verifier, or deployment/merge input.

The approved direction remains the full ReMe fork from FHM-007, with Hermes retaining the provider boundary and the approved crash-safe deterministic commit design (Option B). Model output remains a proposal; Hermes must bind any durable effect to request identity, source-transcript hash, profile/agent/session and note ownership, and an application-controlled marker. FHM-005 remains the independent P0 fail-closed verifier, outside and above candidate model, storage, retrieval and worker logic. Nothing in this assessment broadens FHM-006, FHM-011 or the approved architecture.

“Keep” below means retain as a future research hypothesis. “Discard” means reject direct runtime adoption or replacement, not that the upstream project has no useful ideas. The source claims are hypotheses unless the cited immutable tree and path were inspected. In particular, historical source behaviour is not a claim about a current head, a release not audited, or the Fermes fork.

## Adoption paths

| Path | Benefit | Cost and condition |
|---|---|---|
| Direct integration | Fastest access to an upstream API. | Highest coupling, supply-chain, data-egress and authority risk; none qualifies now. Requires exact pin, licence/NOTICE, lockfile, isolation, provenance, crash/replay and independent review. |
| Selective extraction | Reuses a bounded algorithm or adapter idea. | Requires reimplementation, attribution and a fresh dependency/security review. Output must be a source-bound proposal behind Option B and FHM-005; no upstream store or model-directed delete. |
| Pattern reuse | Lowest runtime coupling: schemas, leases, Git conflict records, staged evaluation and review flows. | Benefits are narrower and engineering remains Fermes-owned. Use only where a measured gap exists; preserve controls and do not import implied trust. |
| Native | Keeps bounded worker/terminal capability already in Hermes and avoids another package. | Native does not mean isolated: capability inheritance and host execution remain. Only test/read-only, least-privilege, bounded and sandboxed use is admissible. |

## Evidence status and reviewer qualification

The independent reviewer verdict is **CONDITIONAL**. This synthesis corrects the acceptance-relevant gaps by using the independently fetched and hashed exact pinned licence files, correcting LCM-X to `plugin/LICENSE`, resolving Graphiti’s short release SHA while explicitly marking that release unaudited, separating original Letta from Letta Code, and separating old SkillHone from current Node/TypeScript SkillHone. It also records the exact Fermes baseline and limits worker evidence to historical upstream Hermes plus confirmed source presence.

Limitations remain and are not candidate adoption qualification: no code was executed, no dependencies were installed or resolved, no bug or crash/replay report was reproduced, no live E2E PASS was obtained, and no live worker isolation, authority, profile-boundary or provider-egress test was run. The assessment makes no implementation claim about the current Fermes branch beyond the supplied baseline and source-presence checks. Research findings cannot authorise an implementation PR, merge, deployment, automatic skill mutation, cloud sync or replacement of ReMe/Option B/FHM-005.
